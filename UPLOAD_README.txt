PROJECT 52 V42 — THE TOTAL REBUILD

FOR THE CURRENT PROJECT-52-V40 GITHUB PAGES APP

1. Keep your existing tracker available and make a full backup from Data first.
2. Open the Project-52-V40 repository on GitHub.
3. Upload every file and the assets folder from this package into the repository root.
4. Allow GitHub to replace files with matching names, then commit the upload.
5. Wait for GitHub Pages to finish deploying and open:
   https://heymann-dev.github.io/Project-52-V40/?v=42#home
6. Refresh once while online. If the prior design remains, close and reopen the
   installed app or perform one hard refresh so the new offline shell is cached.
7. Open Data > V42 System Check and run it. The Reset Mobile Layout control
   clears only saved panel-collapse preferences if the phone retained a stale layout.

IMPORTANT DATA RULES

- This is Project 52 V42. It keeps the familiar military field-command and
  stone-wall identity while beginning a new August 1–December 31 active phase.
- The active phase starts at Level 0 with zero active XP, streaks, time-based
  qualifications, stickers, and progress. Previous evidence is preserved in the
  read-only PREVIOUS PROJECT 52 ARCHIVE.
- Daily completion requires Critical + Body + Life Missions, the quick four-area
  pain review, and one meaningful Rebuild Entry. A legitimate Recovery version
  counts when it is the correct assignment; the Optional Power Move never does.
- The weekly training board targets three rolling chin-up exposures and three
  medically permitted lower-body exposures. Current restrictions always override
  the template.
- The 52-Day Wall, 52 Stones Laid, and Four Cornerstones badges are permanent
  evidence patches. The Home wall course tracks the active Zero-Tolerance streak;
  a lapse resets that active course but never removes an earned badge.
- Uploading these app files does not require importing or resetting your data again
  when you are updating the same GitHub Pages app in the same browser.
- Import the separate V42 private backup only for a fresh installation or a
  deliberate restore. Importing it again can overwrite newer local entries.
- Never upload the private-reset JSON or personal photos to a public GitHub repository.
- After deployment, verify History, Goals, Cash, Photos, Recovery, Mountains, and Data.

The upload package contains app code and public visual assets only. Personal records
remain in the browser unless you deliberately import a backup.
